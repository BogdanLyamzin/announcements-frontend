# Сусіди — фронтенд дошки оголошень

Локальна заготовка для практики на Next.js App Router, React і TypeScript. Інтерфейс українською мовою. Застосунок підключається до REST API з **двох домашніх завдань** і працює з реальними даними студентського бекенду.

Перша практика: [Дошка оголошень у реальному часі](TASK.md) — 50 хвилин.

Друга практика: [Завдання з контейнеризації](DOCKER_TASK.md) — 50 хвилин.

## Запуск

Потрібні Node.js 22.18+ (для тестів) і запущений студентський API з PostgreSQL та застосованими міграціями.

Команди для PowerShell:

```powershell
git clone https://github.com/BogdanLyamzin/announcements-frontend.git
cd announcements-frontend
Copy-Item .env.example .env.local
npm ci
npm run dev
```

Відкрийте **http://localhost:3001**. За замовчуванням бекенд очікується за адресою **http://127.0.0.1:3000**.

Налаштування в `.env.local`:

```dotenv
BACKEND_URL=http://127.0.0.1:3000
NEXT_PUBLIC_UPLOADS_ENABLED=true
NEXT_PUBLIC_UPLOAD_FIELD=image
NEXT_PUBLIC_SOCKET_URL=http://localhost:3000
```

- Якщо API використовує префікс `/api`, задайте `BACKEND_URL=http://127.0.0.1:3000/api`.
- Назва поля фотографії в ДЗ не зафіксована. Значення `NEXT_PUBLIC_UPLOAD_FIELD` має збігатися з аргументом `multer.single(...)`, наприклад `image` або `photo`.
- За замовчуванням POST/PATCH оголошень надсилаються як `multipart/form-data`, зокрема й запити без фото: це варіант другого ДЗ. Поле `price` у multipart передається рядком — бекенд має перетворювати його на число перед числовою валідацією та записом у Prisma.
- Для першого ДЗ без завантаження фотографій задайте `NEXT_PUBLIC_UPLOADS_ENABLED=false`: форма приховає вибір фото й надішле JSON із числовим `price`.
- Після зміни `.env.local` перезапустіть Next.js. Публічні змінні фіксуються під час збірки.
- Якщо фото ввімкнені, бекенду потрібні робочі налаштування Cloudinary. На клієнті дозволені JPG/PNG/WebP до 5 МБ; сервер має перевіряти файл самостійно.

## Готові екрани

| Адреса | Можливості |
| --- | --- |
| `/` | Загальнодоступна дошка, пошук за назвою, сортування, серверна пагінація та ручне оновлення |
| `/register` | Реєстрація з автоматичним входом за відповіддю з ДЗ |
| `/login` | Вхід і повернення до створення або редагування після автентифікації |
| `/announcements/new` | Створення оголошення з необов’язковим фото |
| `/announcements/:id` | Повне оголошення, автор, посилання на email і видалення з підтвердженням |
| `/announcements/:id/edit` | Редагування власного оголошення, частковий PATCH і заміна фото |

Усі відвідувачі бачать усі оголошення. Створення доступне після входу. Кнопки редагування та видалення бачить лише автор; остаточну перевірку прав виконує бекенд.

Передбачені стани завантаження, порожнього списку, відсутності результатів, помилок мережі, 404, 403 та завершення сесії. Категорія зберігається в оголошенні; фільтрації за категорією немає, оскільки відповідний query-параметр не вимагається в ДЗ. Ціна відображається у гривнях.

## Контракт API

Шляхи нижче наведені відносно `BACKEND_URL`. Відповіді очікуються безпосередньо у форматі ДЗ, без додаткової обгортки `result` або `payload`.

| Метод і шлях | Запит | Відповідь |
| --- | --- | --- |
| POST `/auth/register` | `{ username, email, password, name }` | 201 `{ user, accessToken, refreshToken }` |
| POST `/auth/login` | `{ username, password }` | 200 `{ user, accessToken, refreshToken }` |
| POST `/auth/refresh` | `{ refreshToken }` | 200 `{ accessToken, refreshToken }` |
| POST `/auth/logout` | Bearer access token | 204 без тіла |
| GET `/auth/me` | Bearer access token | Об’єкт користувача |
| GET `/announcements?search=&sort=newest&page=1` | — | `{ data, pagination: { total, page, totalPages, perPage } }` |
| GET `/announcements/:id` | — | Об’єкт оголошення з `user` |
| POST `/announcements` | Поля оголошення, необов’язковий файл | 201 об’єкт оголошення |
| PATCH `/announcements/:id` | Лише змінені поля, необов’язковий файл | 200 об’єкт оголошення |
| DELETE `/announcements/:id` | — | 204 без тіла |

`User`: `id`, `username`, `email`, `name`, необов’язковий `createdAt`.

`Announcement`: `id`, `title`, `description`, `price`, `category`, `createdAt`, `updatedAt`, `user`, необов’язковий `imageUrl`. Категорії: `sale`, `service`, `job`, `other`.

Під час реєстрації пароль має містити щонайменше 6 символів, ім’я — щонайменше 2, username — від 3 до 30. Заголовок оголошення — 5–50 символів, опис — щонайменше 10, ціна — більша за нуль. Фронтенд відповідає вимогам **домашнього завдання**, які місцями відрізняються від прикладів лекції.

## Автентифікація та запити

Браузер звертається до `/api/backend/*` на власному origin. Серверний Route Handler Next.js пересилає дозволені запити в Express, зберігає HTTP-статуси, query-параметри та multipart boundary. Це невеликий адаптер: бізнес-логіка оголошень і база даних залишаються в студентському API.

Відповіді register/login/refresh містять JWT згідно з ДЗ. Next.js зберігає їх у HttpOnly cookies `board_access` і `board_refresh`, а клієнту повертає лише користувача або статус. Токени не потрапляють у localStorage чи клієнтський React state. За HTTPS cookies отримують атрибут `Secure`.

Тіло запиту `/auth/refresh` та Bearer-заголовок формує адаптер. При 401 клієнт один раз оновлює пару токенів і повторює початковий запит; одночасні запити однієї вкладки використовують спільний запит refresh. При 429 або помилці мережі автоматичних повторів немає.

Список маршрутів адаптера обмежений контрактом ДЗ. Запити на зміну даних зі стороннім Origin відхиляються. Для REST-запитів CORS між браузером та Express не потрібний, оскільки сервер Next.js звертається до API сам.

**Майбутнє Socket.IO-з’єднання буде прямим**: для нього потрібно окремо дозволити origin `http://localhost:3001` на бекенді.

## Де продовжити практику

Оновлення в реальному часі **ще не реалізоване**: немає Socket.IO-з’єднань, таймерів опитування чи автоматичного оновлення іншої вкладки. Пакет `socket.io-client` уже встановлений.

- `src/hooks/use-announcements.ts` — завантаження списку та функція `refreshAnnouncements()`. Тут є позначка `TODO(practice)` для майбутньої підписки на події.
- `src/components/board.tsx` — відображення списку, пошук, сортування та сторінки. Вони вже використовують спільний хук.
- `src/lib/api.ts` — REST-запити та повтор запиту після refresh.
- `src/lib/types.ts` — типи контракту.
- `src/components/announcement-form.tsx` — створення та часткове оновлення.
- `src/components/announcement-details.tsx` — перегляд і видалення.

Зараз список оновлюється при відкритті сторінки, зміні пошуку, сортування чи номера сторінки, а також після натискання «Оновити список». Після власної операції користувач переходить на сторінку результату або списку. Друга відкрита вкладка залишається незмінною — це початкова поведінка для практики.

Вимоги до змін бекенду та фронтенду наведені в [завданні для студентів](TASK.md).

## Перевірка

```powershell
npm run type-check
npm test
npm run build
npm run test:integration
```

Інтеграційний сценарій запускає окремий production-сервер Next.js і **тестовий HTTP API** з даними в пам’яті. Він перевіряє HTTP-контракт адаптера, multipart, cookies, ротацію токенів, помилки прав доступу та недоступність API. Цей сценарій не замінює перевірку зі студентською реалізацією на PostgreSQL і Cloudinary.

Тестовий API не імпортується застосунком і не використовується під час звичайного запуску.

Для окремої ручної перевірки з тестовими даними можна запустити `node tests/fixture-api.mjs` і тимчасово задати `BACKEND_URL=http://127.0.0.1:4000`. Тестовий акаунт — `olena` / `secret123`; у справжньому API такого акаунта може не бути. Після перевірки поверніть адресу власного сервера.

Шрифт Manrope завантажується через Google Fonts; без мережі використовуються системні шрифти. Ілюстрації складаються з CSS та іконок, а оголошення й фотографії надходять лише з підключеного API.

Довідка про серверний адаптер: [офіційна документація Next.js Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers).
