# Сусіди — фронтенд доски объявлений

Локальная заготовка для практики на Next.js App Router, React и TypeScript. Интерфейс на украинском. Подключается к REST API из **двух домашних заданий**, работает с настоящими данными студенческого бэкенда. Исходники уроков и бэкенд не изменены.

Текст практического задания для студентов: [Дошка оголошень у реальному часі](TASK.md) (50 минут).

Вторая практика: [Контейнеризація дошки оголошень](DOCKER_TASK.md) (50 минут). Основной результат — Dockerfile и запуск фронтенда; подготовка бэкенда и Compose выполняются по мере готовности.

## Запуск

Нужен Node.js 22.18+ (для тестов) и запущенный студенческий API с PostgreSQL и миграциями.

```powershell
cd C:\GoIT\MCS_10_Node.js\practice\announcements-frontend
Copy-Item .env.example .env.local
npm install
npm run dev
```

Открыть **http://localhost:3001**. Бэкенд по умолчанию ожидается по адресу `http://127.0.0.1:3000`.

В `.env.local`:

```dotenv
BACKEND_URL=http://127.0.0.1:3000
NEXT_PUBLIC_UPLOADS_ENABLED=true
NEXT_PUBLIC_UPLOAD_FIELD=image
NEXT_PUBLIC_SOCKET_URL=http://localhost:3000
```

- Если API использует префикс `/api`, задать `BACKEND_URL=http://127.0.0.1:3000/api`.
- Имя поля фото в ДЗ не зафиксировано. `NEXT_PUBLIC_UPLOAD_FIELD` должно совпадать с аргументом `multer.single(...)`, например `image` или `photo`.
- По умолчанию POST/PATCH объявлений отправляются как `multipart/form-data`, включая запросы без фото: это вариант второго ДЗ. Поле `price` в multipart передаётся строкой — бэкенд должен преобразовывать его в число перед числовой валидацией/записью в Prisma.
- Для первого ДЗ без загрузки фотографий задать `NEXT_PUBLIC_UPLOADS_ENABLED=false`: форма скроет фото и отправит JSON с числовым `price`.
- После изменения `.env.local` перезапустить Next.js. Публичные переменные фиксируются при сборке.
- Если фото включены, бэкенду нужны рабочие настройки Cloudinary. Ограничения выбора фото на клиенте: JPG/PNG/WebP, до 5 МБ; сервер обязан проверять файл самостоятельно.

## Готовые экраны

| Адрес | Возможности |
| --- | --- |
| `/` | Общедоступная доска, поиск по названию, сортировка, серверная пагинация, ручное обновление |
| `/register` | Регистрация с автоматическим входом по ответу ДЗ |
| `/login` | Вход, возврат к созданию/редактированию после авторизации |
| `/announcements/new` | Создание объявления, необязательное фото |
| `/announcements/:id` | Полное объявление, автор, ссылка на email, удаление с подтверждением |
| `/announcements/:id/edit` | Изменение своих объявлений, частичный PATCH, замена фото |

Все видят все объявления. Создание доступно после входа. Кнопки редактирования и удаления видны только автору; окончательную проверку прав выполняет бэкенд. Предусмотрены загрузка, пустой список, отсутствие результатов, ошибки сети, 404, 403 и истечение авторизации. Категория сохраняется в объявлении; фильтрации по категории нет, поскольку такой query-параметр в ДЗ не требуется. Цена отображается в гривнах.

## Контракт API

Пути ниже указаны относительно `BACKEND_URL`. Ответы ожидаются непосредственно в формате ДЗ, без дополнительной обёртки `result`/`payload`.

| Метод и путь | Запрос | Ответ |
| --- | --- | --- |
| POST `/auth/register` | `{ username, email, password, name }` | 201 `{ user, accessToken, refreshToken }` |
| POST `/auth/login` | `{ username, password }` | 200 `{ user, accessToken, refreshToken }` |
| POST `/auth/refresh` | `{ refreshToken }` | 200 `{ accessToken, refreshToken }` |
| POST `/auth/logout` | Bearer access token | 204 без тела |
| GET `/auth/me` | Bearer access token | Объект пользователя |
| GET `/announcements?search=&sort=newest&page=1` | — | `{ data, pagination: { total, page, totalPages, perPage } }` |
| GET `/announcements/:id` | — | Объект объявления с `user` |
| POST `/announcements` | Поля объявления, необязательный файл | 201 объект объявления |
| PATCH `/announcements/:id` | Только изменённые поля, необязательный файл | 200 объект объявления |
| DELETE `/announcements/:id` | — | 204 без тела |

`User`: `id`, `username`, `email`, `name`, необязательный `createdAt`.

`Announcement`: `id`, `title`, `description`, `price`, `category`, `createdAt`, `updatedAt`, `user`, необязательный `imageUrl`. Категории: `sale`, `service`, `job`, `other`.

Пароль при регистрации — минимум 6 символов, имя — минимум 2, username — 3–30. Заголовок — 5–50, описание — минимум 10, цена — больше нуля. Фронтенд следует требованиям **домашнего задания**, которые местами отличаются от примеров лекции.

## Авторизация и запросы

Браузер обращается к `/api/backend/*` на origin Next.js. Route Handler пересылает разрешённые запросы к Express, сохраняет статусы, query-параметры и multipart boundary. Это небольшой адаптер, не новый бэкенд объявлений: бизнес-логика и база остаются в студенческом API.

Ответы register/login/refresh содержат JWT согласно ДЗ. Next.js сохраняет их в HttpOnly cookies `board_access` и `board_refresh`, а клиенту возвращает только пользователя/статус. Токены не попадают в localStorage или клиентский React state. При HTTPS cookies получают `Secure`. Тело `/auth/refresh` и Bearer-заголовок формирует адаптер. При 401 клиент один раз обновляет пару токенов и повторяет исходный запрос; одновременные запросы одной вкладки разделяют один refresh. При 429 или сетевой ошибке автоматических повторов нет.

Список маршрутов адаптера ограничен контрактом ДЗ. Запросы изменения данных с посторонним Origin отклоняются. Для REST CORS между браузером и Express не требуется, поскольку сервер Next.js обращается к API сам. **Будущее Socket.IO-соединение будет прямым**, и для него потребуется отдельно разрешить origin `http://localhost:3001` на бэкенде.

## Где продолжить практику

Реальное время **ещё не реализовано**: нет соединений Socket.IO, таймеров опроса, автоматического обновления другой вкладки. Пакет `socket.io-client` уже установлен.

- `src/hooks/use-announcements.ts` — загрузка списка и `refreshAnnouncements()`. Здесь есть метка `TODO(practice)` для будущей подписки на события.
- `src/components/board.tsx` — отображение списка, поиск, сортировка и страницы. Они уже используют общий хук.
- `src/lib/api.ts` — REST-запросы и повтор запроса после refresh.
- `src/lib/types.ts` — типы контракта.
- `src/components/announcement-form.tsx` — создание и частичное изменение.
- `src/components/announcement-details.tsx` — просмотр и удаление.

Сейчас список обновляется при открытии страницы, изменении поиска/сортировки/страницы и нажатии «Оновити список». После своей операции пользователь переходит на страницу результата или списка. Вторая открытая вкладка остаётся неизменной — это исходное поведение для практики. Требования к изменениям бэкенда и фронтенда описаны в [задании для студентов](TASK.md).

## Проверка

```powershell
npm run type-check
npm test
npm run build
npm run test:integration
```

Интеграционный сценарий запускает production Next.js и отдельный **тестовый HTTP API** с данными в памяти. Он проверяет HTTP-контракт адаптера, multipart, cookies, ротацию, ошибки прав и недоступность API. Он не заменяет проверку со студенческой PostgreSQL/Cloudinary-реализацией. Тестовый API не импортируется приложением и не используется при обычном запуске.

Для отдельной ручной проверки с тестовыми данными можно запустить `node tests/fixture-api.mjs` и временно задать `BACKEND_URL=http://127.0.0.1:4000`. Тестовый аккаунт — `olena` / `secret123`; его нет в настоящем API. После проверки верните URL своего сервера.

Шрифт Manrope загружается через Google Fonts; без сети используются системные шрифты. Иллюстрации состоят из CSS и иконок, объявления и фотографии берутся только из подключённого API.

Справка по серверному адаптеру: [официальная документация Next.js Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers).
